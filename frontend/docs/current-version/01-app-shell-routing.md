# 앱 셸과 라우팅

## 부트스트랩과 전역 상태

`main.tsx`는 Strict Mode에서 앱을 실행한다. `ToastProvider`는 하위 Provider보다 바깥에 있어 페이지와 컨텍스트가 같은 오류 알림 큐를 사용한다. `AuthProvider`는 저장 세션 복구와 로그인 상태를, `FriendsProvider`는 친구·요청 목록과 새로고침 함수를 제공한다.

`App.tsx`는 공통 `Header`, 본문 `Routes`, 작품 상세 오버레이, 로그인 사용자의 플로팅 친구 허브를 조립한다. 정책·로그인·가입 페이지와 오버레이 상태에서는 화면을 가리는 플로팅 액션을 숨긴다.

## 작품 상세 오버레이

목록 카드가 `backgroundLocation`을 라우터 state에 넣으면 주소는 `/anime/:id`로 바뀌지만 본문 라우트는 이전 위치를 계속 렌더링한다. 그 위에 별도의 dialog 패널이 `AnimeDetailPage isOverlay`를 렌더링한다. 닫기는 이전 위치로 돌아가며 직접 주소로 접근하면 일반 상세 페이지로 열린다.

이 방식은 탐색·내 컬렉션·공개 시리즈 카드에서 공통으로 사용한다. 링크 state의 `fromPage`는 상세 화면이 어느 맥락에서 열렸는지를 남긴다.

## 플로팅 친구 허브

로그인 사용자가 버튼을 열면 친구 컨텍스트를 silent refresh하고 최근 친구 목록을 표시한다. 외부 클릭과 Escape로 닫히며 친구 항목은 해당 사용자의 공개 컬렉션으로 이동한다. 로딩과 정상 빈 목록은 패널 안에서 안내하고, 조회 실패 원문은 전역 toast로 알린 뒤 패널에는 중립적인 대체 문구만 남긴다.

## 라우트 실패 처리

잘못된 동적 파라미터처럼 컴포넌트가 직접 감지한 문제는 오류 원문을 toast로 알린다. 본문은 빨간 오류 카드 대신 열 수 없는 화면이라는 중립 상태와 안전한 이동 수단을 제공한다. 서버 연결이나 필수 데이터 로드 실패는 공통 재시도 상태가 담당한다.
