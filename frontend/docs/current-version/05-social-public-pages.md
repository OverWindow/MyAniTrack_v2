# 친구와 공개 페이지

## 친구 상태

`FriendsProvider`가 친구 목록, 받은 요청, 보낸 요청, 로딩·오류와 갱신 함수를 관리한다. 로그인 이후 초기 데이터를 읽고 친구 요청 전송, 수락·거절, 친구 삭제가 성공하면 관련 목록을 다시 동기화한다. 상단 플로팅 허브와 `/friends` 페이지가 같은 컨텍스트를 사용하므로 한 화면의 변경이 다른 화면에도 반영된다.

친구 페이지는 요약 카드, 친구 목록, 사용자명 요청 폼, 받은·보낸 요청 영역으로 구성된다. 작업 성공은 기존 상태 메시지로 표시하고 실패는 전역 error toast로 알린다.

## 공개 프로필

공개 프로필은 사용자명, 이미지, 소개, 컬렉션 수와 공개 배지를 표시한다. 프로필에서 공개 컬렉션과 공개 분석으로 이동한다. 프로필 본문과 배지는 독립 요청으로 처리해 배지 실패가 프로필 전체를 막지 않는다.

공개 컬렉션은 대상 사용자의 작품 기록과 시리즈 진행을 읽기 전용으로 보여준다. 공개 분석은 내 분석과 같은 차트 구조를 사용하지만 대상 `userId`가 포함된 공개 통계 API를 호출한다. 작품 드릴다운과 성우 랭킹도 대상 사용자의 컬렉션을 기준으로 한다.

## 가시성·차단·신고

공개 사용자 API는 선택적 인증 후 `requireVisibleUser`를 통과한다. 대상 계정이 정지 상태이거나 로그인 요청자와 어느 방향으로든 차단 관계이면 존재하지 않는 사용자와 같은 404 응답을 사용한다. 공개 작품·시리즈 결과에서도 성인 작품과 운영자가 숨긴 작품은 제외된다.

프로필 신고는 정해진 사유를 선택해 제출하며 관리자는 신고 당시 정보와 누적 요청을 확인할 수 있다. 자기 자신 신고·차단과 지원하지 않는 사유는 백엔드가 거부한다.

## 실패와 빈 상태

없는 사용자, 잘못된 경로, 차단된 사용자는 오류 원문을 toast로 알리고 본문에는 열 수 없는 화면과 안전한 복귀 경로를 둔다. 친구 없음, 공개 작품 없음, 검색 결과 없음은 오류가 아닌 정상 빈 상태로 처리한다.
